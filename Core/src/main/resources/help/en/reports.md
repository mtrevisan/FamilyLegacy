# Reports

The **Reports** menu produces documents from the data of the file; its commands are in four groups, separated in the menu and in the table below: the ones about people and groups, the ones about a place, a source or a research question, the bibliography and the research progress, and the ones about the whole file. All fifteen reports open the same dialog, and each writes one file in the format you choose when you save it.

## The reports

| Report | Available when | Starts from |
|---|---|---|
| **Ancestor Report...** | an individual is selected | the selected individual |
| **Descendant Report...** | an individual is selected | the selected individual |
| **Individual Summary...** | an individual is selected | the selected individual |
| **Relationship Report...** | an individual is selected | the selected individual |
| **Family Group Sheets...** | an individual is selected | the selected individual |
| **End of Line...** | an individual is selected | the ancestors of the selected individual that have no known parents |
| **Group Sheet...** | a group is selected | the selected group |
| **Place Report...** | the file has a place | a place: the selected one, or the one you pick from the list |
| **Source Report...** | the file has a source | a source: the selected one, or the one you pick from the list |
| **Research Question Report...** | the file has a research question | a question: the selected one, or the one you pick from the list |
| **Bibliography...** | the file has a source or a media record, and a record is selected | the selected record |
| **Research Progress...** | the file has a research question or a task, and a record is selected | the selected record |
| **Family Book...** | the file has an individual | the whole file: everybody |
| **Full Bibliography...** | the file has a source | the whole file: every source |
| **To Verify...** | the file has an individual or a source | the whole file: what is still to look at |
| **Conflicts...** | the file has an individual | the whole file: the conflicts between competing assertions |
| **Surnames by Place...** | the file has an individual | the whole file: the surnames of each place |
| **Identity Hypotheses...** | the file has an identity hypothesis | the whole file: the possible duplicates and where each stands |

Select the person or group you want in the tree **before** you open the report. Places, sources and research questions cannot be selected in the tree: for the *Place*, *Source* and *Research Question* reports a list opens first, to pick the record (if a record of that kind is already selected, it is used without asking). The first line of the dialog, *Target Subject*, tells which record it will use. Every report is about a record, so the commands stay greyed out until one is selected (or, for the three above, until the file has one; the *Full Bibliography*, the *Family Book*, *To Verify* and *Surnames by Place* are about the whole file and need no selection: the first line of their dialog says so), and **Generate...** refuses to write a report without a subject. The *Bibliography* lists the sources cited by that record (by its events, attributes and relationships), not those of the whole file.

## The dialog

From the top:

1. **Target Subject**: the record the report is about.
2. **Language** of the document, see [Language](#language). It starts as the language of the application, until you choose another.
3. **Saved options**: named sets of the options of this report, see below.
4. The **options**, see below.
5. The **page layout**, see below.
6. **Restore Defaults** and **Generate...** (`Esc` closes the dialog). **Generate...** asks where to save the report and in which format: the *Save as type* list has *Plain Text (.txt)*, *Markdown (.md)* (the default), *HTML (.html)*, *Word (.docx)*, *PDF (.pdf)*, *EPUB (.epub)* and *Static Website (folder)*, but only the formats that are installed (see [The formats](#the-formats)); changing the format changes the extension of the suggested name. One format at a time: to have more, generate again.

**The dialog remembers your choices.** When you press **Generate...** and choose a folder, the dialog keeps the format you chose, the PDF font (see below), the language, the folder, the page layout, and the options of that kind of report (the *Ancestor Report* and the *Descendant Report* each have their own), and offers them again next time, also after the application is closed. **Restore Defaults** brings back the default options and page layout, the automatic PDF font, the language of the application and the default format (Markdown). The **privacy policy** is the exception: it is never remembered and **always starts at Hide Confidential**, so that a choice made for a private report is not carried by mistake to one you will share. Hover over an option to read a short description of it.

**The dialog shows only the options that the report uses.** An option that would change nothing in that report is not listed (for example, the ancestry options in the *Group Sheet*, the group options in an *Individual Summary*, or the timeline in an *Ancestor Report*), and a heading with no options left disappears. An option that the report always applies is shown **ticked and greyed out**, with a tooltip saying so (for example, *Direct relations* in the *Relationship Report*). What each report does with each option is in [What each report contains](#what-each-report-contains).

### Where the files go

**Generate...** opens the dialog that asks where to save the file, in the **folder of the last report** (if there was one). The name it proposes is that of the **subject and the kind of report**: `Antonia_Pastrelo_I1430-ancestor_report` (only the kind, `family_book_report`, `to_verify_report`..., for a report of the whole file), with the extension of the format (the static website is a **folder**, named like `individual_report_site`). **If a file with the same name is already there, you are asked before it is overwritten.** A progress window with a **Cancel** button follows, and at the end a message lists the files written, with **Open Directory** to see them in the file manager. The reports are not opened for you.

Images are not copied next to the file in every format: Markdown and HTML refer to the original media files (with paths relative to the folder, when possible), so keep the media where they are; Word, PDF and EPUB embed the images when the report is made; the static website copies them into the `images` folder inside its own folder.

## The options

**Privacy**

- **Privacy policy**: *Show All*, *Hide Confidential* or *Hide Restricted and Confidential*, as in **View > Privacy**. It is independent of that menu and **always starts at Hide Confidential**. See [Privacy](privacy.md#reports).
- **Living persons**: what the report says of the persons who **may be living** (the ones with no death, and not born more than 110 years ago), and of everything about them. *Hide everything*: they are left out as if they were not in the file, with their events, attributes, media, notes, citations and relationships. *Name and role only* (the default): they are listed with their name and their role in the family (child of, spouse of, member of a group), and nothing else: no dates, places, sex, notes, citations or picture. *Show everything*: they are shown like anybody else, as the privacy policy says. It applies to **every** report, and **always starts at Name and role only**, like the privacy policy: it is not remembered. It has no effect (and is greyed out) when the privacy policy is *Show All*. A person with a privacy setting of their own (a declared level) follows that setting, not this choice. The names of the living persons can still appear in the title of a source or of a photo (*Trevisan Emilio + Trevisan Mauro 1990*): rename those if they must not be seen.
- **Show privacy details**: under each record that has a privacy setting, prints its level, reason and expiry.
- **Audit trail**: adds the creation and update comments of each record.
- **Document header**: adds a *Document information* section, if the file has a header.

**Narrative**

- **Introduction**, **Descendants**, **Paternal ancestry**, **Maternal ancestry**, **Direct relations** (off by default: the *Relationship Report* is made for them) and **Indirect relations** (off). The descendants are drawn as a tree, each person with the years of birth and death and the spouses, the children from the eldest to the youngest; a person already drawn is marked *(see above)* and not repeated with the branch.
- **Collaterals** decides who is included besides the direct line, for the ancestor and descendant reports only:
  - *none* (default): the direct line only.
  - *spouses*: plus the spouses.
  - *siblings*: for ancestors, plus the siblings of the ancestors (uncles and aunts) and their spouses; for descendants, plus step-children.
  - *cousins*: plus the descendants of those siblings (or of the step-children).
  - *extended*: everyone connected by any documented relationship, associates included.
- **Order of persons**, for the *Family Book* only: *By family name* (default; then by the other names; whoever has no name comes last) or *By birth date* (the oldest first; whoever has no birth year comes last, in alphabetical order).
- **Generations**, for the ancestor and descendant reports only, decides how far to follow the line: *All* (default), or from 1 to 20 generations (the parents, or the children, are the first). The person the report is about is not counted, and the tree, the list of persons and the collaterals stop there.
- **First generation**, for the same reports, leaves out the earlier generations from the chapters: *The subject* (default) starts from the person the report is about, 1 from the parents (or the children), and so on. The numbers of the persons stay what they are, and the tree still shows the whole line. With the same value as *Generations*, the report is about that generation only (the peer generation: for instance, only the grandparents).
- **Order of generations**, for the same reports, puts the chapters from the generation nearest to the subject (default) or from the farthest. Each person has a chapter that starts on a new page whichever the order is.

**Content sections**: **Notes**, **Sources**, **Media**, **Historic events**, **Repositories** (on), **Include original sources** (on), and **Historic context & research**, **Cultural norms**, **Evidence qualifiers** (off).

**Narrative style** decides how the persons are named and numbered:

- **Numbering**, for the *Ancestor* and *Descendant* reports: the number of each person is written before the name in the heading of the chapter, in the index (a column *No.*) and in the tree. *Automatic* (default) uses *Ahnentafel* for the ancestors (the person is 1, the father of the number n is 2n and the mother 2n + 1; a person that is an ancestor twice has the lowest number) and *d'Aboville* for the descendants (the person is 1, the children, the eldest first, are 1.1, 1.2, ..., and the children of 1.2 are 1.2.1, 1.2.2, ...). *Henry* is the other system for the descendants (1, 11, 12, 121, ...; the tenth child is X). A system for the other direction is replaced by the automatic one. *No numbers* leaves them out. The collateral relatives have no number.
- **Numbers of the persons in brackets** (off): where the text names another person that has a number (the spouse, the children), the number follows the name in brackets (`Sara Neri [1.1]`), so the reader can find the chapter. It needs a numbering.
- **Direct ancestors in bold** (off): the direct ancestors of the person the report is about are in bold wherever they are named (the text, the index and the list of the persons).
- **Given names**: *All the given names* (default) or *First name and initials* (`Giovanni B. Rossi`). The family name is always in full.
- **Unknown name**: the text written for a person that has no name (for example `?`). Empty (default): the identifier of the person.

**Notes and sources** decide where the longer texts are written, in the chapter of each person:

- **Notes** and **Text of the sources** (the extract of a citation, its note and its crop): *Inline, where they belong* (default); *In a section*, where the note is replaced by a reference (`[Note 1]`, `(Extract 1)`) and the text is in the **Notes** section, or in the **Citations** section, of the person, under the same number; or *Long ones in a section*, where only the texts longer than the limit move.
- **A long text is over (lines)**: the limit of the *Long ones in a section* placement. A line is about 90 characters, and every line break starts another one.
- **Principal sources only** (off): of the sources that cite the same event, attribute or relationship, only the best ones are told: the ones with the highest weight (one for each citation that supports it, plus one for an original source, one for primary information and one for direct evidence). A source that contradicts what it is cited for is always told.
- **Page of the source** (on): the locator (page, folio...) of the source in each citation. Without it the citation is the title of the source. The quality of the source is the **Evidence qualifiers** option.

**Images and media** decide where the pictures are and how they are embedded:

- **Media**: *In a section* (default), once for the whole report after what the persons cite; *In the chapter of each person*, in a section of the chapter (the media of groups, in the *Family Book*, stay in the final section); *In an appendix*, after the indexes, titled *Appendix: Media*; or *One image on each page*. A report on a source, a place or a group has the choice of the sections only, and the *Bibliography* and the *Research progress* have the section always.
- **Images per page**: a new page after as many images of the media as chosen (*As it is*: the format decides).
- **Largest image (Mpx)**: an image with more pixels (in millions) is reduced when the report is made, with the same proportions; the file of the image is not changed. A reduced copy is written in the temporary folder and removed when the application closes.
- **Portrait size (px)**: the longest side of the portrait of a person in the chapter; it is reduced, never enlarged.
- **Portrait of a person (cut from a larger photo)**: it matters only when the preferred image of a person is a region of a larger photo. *Show the whole photo* (default), with the region of the portrait in the caption; *Show only the cut-out portrait*, the region the portrait is cut to; or *Cut-out portrait; omit the whole photo from Media*, where the picture is left out of the media too, as the portrait is what is wanted of it.
- **Name as the title of the portrait**: the caption of the portrait is the name of the person.
- **Portrait position**: where the portrait is in the text. *As the format does* (default) leaves it centred in PDF and Word and as a block in a web page; *Left*, *Centred* and *Right* put it on that side; *Left, text around it* and *Right, text around it* let the text flow beside it (PDF, HTML, web site and e-book). Word puts the portrait on that side without the text around it, and Markdown and plain text have no position.

**Group sources by kind** (off) lists the sources of the *Sources* section, and of the *Full Bibliography*, under a heading for each kind of source (census, church register, military record...), in the order of the list of kinds of the source editor, then the kinds you wrote yourself, then the sources without a kind; inside each group they are alphabetical. A source that has a kind shows it as **Kind** in the reports that describe a source. The option is not shown in the *Source Report*, which is about a single source.

**Include original sources** acts on the *Sources* section: when a cited source is derived from others (a copy of a transcription of a register), those are listed too, after the cited ones, marked *Not cited directly*, so that a bibliography never gives the transcription without the register behind it. Turn it off to list only what is cited. The *Full Bibliography* has every source already, and does not show the option.

In every report that describes a source (the *Source Report*, the *Sources* sections and the *Full Bibliography*), a source that is derived from others says **Derived from** (the sources it is made from, with the locator, and *(Contradicts)* if it disagrees with them) and, if the chain is longer, **Original** (the sources at the top of it). The *Source Report* also lists the **Derived sources**: those made from it.

**Group report**: **Groups and memberships** (on: the *Group memberships* list in the relationships of a person), and, for group roots and for the *Family Book*, **Show group members**, **Show subgroups** and **Show group attributes** (on). In the *Family Book*, **Groups and memberships** also decides whether the groups have a page.

**Diagnostics** (all off): **Full event participants** (adds *Other participants* to each event), **Coverage report** (a table of how complete and how sourced each record is, and the number of records without a source citation) and **Chronological timeline** (a table of the events of the root, with the related historic events; for individual, group and place roots).

**Indexes**: **Index of individuals** and **Index of places** (on). In the *Family Book*, **Index of individuals** also adds the index of the groups. The index of the individuals is in order of family name, then of the other names, with the years of birth and death (the column *Years*, that **Years in the index of individuals** turns off); in a report with a chapter for each person (*Ancestor*, *Descendant*, *Family Book*) each name is a link to the chapter of the person. When a report has more than 40 chapters (a chapter for each person), the *Contents* lists only the chapters that are not about a person: the index leads to those.

**Style**: **Include descriptions** (on): in the Media section, adds the location, description and mapping of each media item. **Include pictures** (on): shows the preferred image of a person or group and the images of the Media section; with it off, the media are listed as links to their files. **Date format** decides how the dates are written: *As recorded* (default, `1888-05-01`), *1 May 1888*, *May 1, 1888* (the months in the language of the report) or *Year only*. Only the dates of the Gregorian calendar that are written in full (day, month and year, or month and year, or the year) are changed: a date that was typed as a text, or that is in another calendar, stays as it is.

**Saved options** keeps named sets of the options of a report (each kind of report has its own). Choose a name in the list and its options are put in the dialog at once (the privacy policy, and what the report does not use, stay as they were); **Save...** keeps the options as they are now under a name (the one chosen, to replace it, or a new one); **Delete** removes the chosen set. The language, the page layout and the privacy policy are not part of a set.

**Page layout (PDF and Word)** is the same for every report, and the other formats ignore it: the **paper** (*A4*, *A5* or *Letter*), the **margin** (*Default*, or from 15 to 40 millimetres), whether the **title of the report is repeated at the top of every page but the first**, a **footnote** (a line at the bottom of every page, under the page number) and the lines of text that go **under the title** on the first page (for example who prepared the report, and for whom).

## What each report contains

**Individual Summary** is the full report on one person. In order: the *Document information* (if on); the **Introduction** (a line saying who it is about, the lifespan, and the number of events, sources and relatives); the **Life of** the person, with the preferred image, the *Personal data*, the *Life events* (one heading each), the *Attributes*, the *Relationships* (with the *Group memberships*), the *Notes*, the *Citations* and the *Audit trail* if on; then the paternal and maternal ancestry, the descendants and the relations (off by default) if on; the timeline; the historic context and research (with identity hypotheses and conclusions); the cultural norms; the historic events; the repositories; the sources; the media; the places; the coverage report; and the indexes.

**Group Sheet** has the *Introduction* and the **History of** the group: the group data, the members (a table with the years, the role and, if any has them, the period of the membership: the parents first, then the children from the eldest to the youngest), the attributes, the groups it belongs to and contains, the events involving the group, the notes and citations; then the same closing sections as above.

**Family Group Sheets** is the classic exchange document of a family: for the selected person, **a sheet for each partner** (the partners in the relationships, and the other parent of the children), with the two **parents** (the name, the date and place of birth, the date and place of death), the **marriage** (date and place, if an event of marriage has both of them as participants) and the **children** of the couple, numbered, from the eldest to the youngest, with the same data. The children for whom the other parent is not known are in a last sheet, *other parent unknown*; a person with no partner and no children has one sheet with no children. A person that the privacy policy shows with the name and role only has no dates or places. The options that apply are the *Document header* and the *Date format*.

**End of Line** is the list of the ancestors of the selected person that have no known parents (the *brick walls* of the research), to see where each line has to be continued. It opens with how many there are, out of how many ancestors, in how many generations, then a table with the **generation** (1 is the parents), the **name** and the date and place of **birth** and **death** of each one, nearest generation first and in alphabetical order inside it. An ancestor is at the end of the line when the file has no parent of theirs at all: with a limit on the generations, an ancestor of the last generation is listed only if they have no parents, however far the report goes. If the person has no known parents, or all the ancestors have them, the report says so. The options that apply are the *Document header*, the *Date format*, the *Generations*, the *Given names* and the *Unknown name*; what the privacy policy hides is left out.

**Place Report** is about one place: the *Place:* section with its names (with type, language and variants), type and coordinates, the **historical jurisdictions** (the places that contained it and the ones it contained, with their dates), the **contained places**, the **events at this place** and the events in which the place is a participant, the attributes recorded at the place, and its notes, citations and audit trail; then the common closing sections (the sources, media, places, and so on, as the options say). It has no *Introduction*, and no ancestry, descendants or group options.

**Source Report** is about one source: the *Source:* section with its title, author, publisher, date, place and type of medium, the **repository** that holds it, its **documents**, and **Cited by**: every citation that refers to the source, grouped by the record that makes it; then notes, evidence, privacy and audit trail, and the common closing sections.

**Research Question Report** is about one question: the *Research question:* section with the question, its status, conclusion and confidence, and then its **targets**, **activities**, **tasks** and **conclusions**, each with the detail of the *Research* section of the other reports; then the common closing sections. It is the report to hand to somebody who works with you on the question.

**Full Bibliography** is the bibliography of the whole file (the *Bibliography* above is the one of a record): the title, how many sources there are, a **table of every source** (title, author, date and how many times it is cited), and then an entry for each source, in alphabetical order, with the same content as the *Source Report*: author, publisher, date and place, the repositories that hold it, its documents and **Cited by** (every record that cites it, with the locator). A source that the privacy policy hides is left out. Only the options that make sense are shown: the document header, the privacy details, the audit trail, notes, sources (the citations of the sources themselves) and evidence.

**Family Book** is the document about everybody in the file: the *Document information* (if on), the title, how many individuals there are, the **Index of individuals** (if on) and, after it, the **Index of groups** (the same option decides both, and it is there only if the book has groups), then, for each person, on a new page, the introduction and the life story, and at the end what they all cite together: the **Repositories**, **Sources** and **Media** (if on), the **Places** and the **Index of places** (if on). The persons are in the *Order of persons* you choose, and the ones the privacy policy hides are left out. After the persons, if **Groups and memberships** is on (it is by default), there is a page for each **group**, in alphabetical order, as in the *Group Sheet*: the introduction and the *History of* the group, with its members, subgroups and attributes as the *Show group...* options say; the sources, media and places of the groups are in the closing sections too. For a large file the book is long, and takes a while to write.

**To Verify** is the list of what a researcher has still to look at in the whole file, to take to an archive, to a study group or to a relative. It opens with how many things there are and a table of the kinds of finding, then a table of records for each kind: the **problems of the file** (the structural checks of *Tools > Validate File*: circles of parentage, dates that cannot be right, and the like; the check of the grammar of the protocol is not repeated here), the **citations that contradict** the record they are on, the **media whose file is not found**, the **individuals with no birth date**, the **vital events** (birth, death, burial, cremation, marriage) **with no date, with no place, or with no source that supports them**, the **sources that no record cites**, and the **research tasks** that are open or in progress. It judges only what is written: a birth that is not recorded is something to find, not an error. The findings of the [research assistant](assistant.md) (research gaps, chronology, identities) are not repeated: the report says so itself. Only the *Document information* option applies; what the privacy policy hides is left out, and the text of the problems of the file is in the language of the application, not in the one of the report.

**Conflicts** is the list of the conflicts between competing assertions of the whole file, the ones that no conclusion has settled yet and the ones that a [conclusion](assistant.md) has: several **births**, **baptisms**, **deaths** or **burials** of an individual whose dates or places cannot all be right (or that are several records that do not contradict each other), **parentage** (more than two biological parents, two of the same sex, an individual who is their own ancestor), **relationships** (the same child and parent both biological and adoptive, foster, guarded or step), **attributes** that can have only one value (national identifier, sex) and **names** (two or more names of the same kind, *birth*, *official*, *religious*, *legal* or *maiden*, written differently; a name cannot be the target of a conclusion, so this conflict ends only when you correct, merge or re-type the names) and **identity hypotheses** that no conclusion has evaluated. It opens with how many conflicts there are, how many are settled, and a table by kind; then, for each kind, each conflict gives the individuals, what is wrong, its **status** (*unresolved*, or what the conclusion says: supported, proven, disproven, no assertion prevails, one assertion preferred), a table of the **competing assertions** (the record, what it asserts, the place, the confidence you gave it, how many citations **support** it and how many **contradict** it), the **conclusion** and the **preferred assertion** if there is one, and the **research questions** that deal with it (the ones the conclusion answers and the ones about the individuals or the records). Three options narrow the list: **Conflicts listed** (all of them, only the unresolved ones, or only the settled ones), **Conflicts about** (events, relationships, attributes, names or identity hypotheses) and **Confidence of the conflicts** (the conflicts in which at least one assertion has the confidence you pick: low, medium, high, or not stated). A conflict is only reported, never decided. Only the *Document information* option applies besides the filter, and a conflict that concerns an individual the privacy policy hides is left out.

**Identity Hypotheses** is the list of the identity hypotheses of the whole file, to manage the research on possible duplicates and to check the file before an export or a publication. A hypothesis has no state of its own: it is **open** when no conclusion evaluates it or the evaluation leaves the question open (*conflicting evidence*, no proof status), **accepted** when the most recent conclusion that evaluates it supports or proves it (the records are still to be merged; merging deletes the hypothesis) and **rejected** when that conclusion disproves it. The report opens with how many hypotheses there are in each state, then a heading for each state (open, accepted, rejected) and, for each hypothesis, the two **records** (with their identifiers), its **status**, the **confidence**, the **rationale**, the **supporting** and **contradicting evidence** (the sources it cites), the **research questions** that deal with it (about the hypothesis, its records or answered by its conclusions) and the **conclusions** that evaluate it. Two options narrow the list: **Hypotheses listed** (all, open, accepted or rejected) and **Possible duplicates of** (individuals, places, sources, repositories or other records). It only lists the hypotheses, it never decides them. Only the *Document information* option applies besides the filters, and a hypothesis that concerns a record the privacy policy hides is left out.

**Surnames by Place** is the list of the surnames of the whole file, for each place, to take to the archive of the place: which families are there, and when. It opens with how many individuals have a surname, how many different surnames there are and how many places, then a heading for each place (by its complete name, "Borgo, Treviso, Veneto", in alphabetical order, with the number of individuals) and a table of its surnames: the **surname** (with its prefix, "de Marco"), how many **individuals** bear it, the **period** (the first and the last year they were born in, "1780–1850") and how many have **no date**. The place and the year are those of the birth; if the birth has none, those of the baptism or the christening (each is looked for by itself: a birth with a date and no place takes its place from the baptism). Whoever has no place is in the last group, *Place unknown*. The surname is the family name of the first name of the individual; the same surname written with different capitals is one, but one written in different ways (*Masutti*, *Mazutti*) is listed in each of them: the file says they are different, and it is for you to say they are not. An individual with no surname is not in the list. Only the *Document information* option applies, and what the privacy policy hides is left out.

**Ancestor Report** and **Descendant Report** have a different structure:

1. the *Document information* and the title (*Ancestors of ...*, *Descendants of ...*);
2. how many individuals the report covers;
3. the **Ancestor tree** (or **Descendant tree**), drawn in text, direct line only; Every person is written with the years of birth and death, as in *Antonia Pastrelo (1633–?)*, and the children from the eldest to the youngest. A person who is already in the tree (two branches that meet again) is not drawn a second time with the whole branch: the line says *(see above)*.
4. the **Collateral relatives**, if *Collaterals* is not *none*, each with its kinship and path;
5. the **Index of individuals**, if on;
6. then, for each person, on a new page, a chapter with the name of the person, and in it, as sections, the introduction and the life story (the personal data, the events, the attributes, the relationships, ...);
7. then, once for all the persons, what they cite together: the **Repositories** and the **Sources** (if on), the **Media** (if on), the **Places** and the **Index of places** (if on).

The per-person pages contain only what is written inside the life story (notes and citations, with the sources written out in the Sources section at the end). The timeline, the coverage report, the historic context and research, the cultural norms and the historic events are not part of these two reports, and the options about ancestry, descendants and relations do not apply to them: the dialog does not show these options.

**Bibliography** and **Research Progress** force some options, and the dialog shows them as such (the bibliography always has the sources, evidence qualifiers, repositories and index of places, and leaves out the narrative and the context, which are not shown; the research progress always has the context and research, the coverage report, the sources, the evidence and the indexes, and leaves out the ancestry, descendants, relations, media and the index of places, which are not shown). Both keep your choices for *Notes*, and for the other options they do not force.

### Things to know about these reports

- **The Relationship Report** is about the **direct and indirect relations** of the person, and nothing of the life: the *Document information*, the *Introduction*, the **direct relations** (the person and the descendants, one table for each generation, the eldest first; each with the years of birth and death, the kinship term and the parents; a descendant through an adoptive, foster or other legal link has the term marked *(legal)*; a person who descends through more than one line is listed once), the **indirect relations** (the spouses and associates of those) and the *Index of individuals*. It has no events, attributes, sources, places or media; the only options it uses are the ones for those sections.
- **Bibliography** and **Research Progress** work on the **selected record**, not on the whole file: for an individual, the bibliography lists the sources cited by that person, their events, attributes and relationships. With an individual selected, the document also begins with that person's life story.

## Language

The **Language** list offers exactly the languages the report can be written in: English and every language for which a translation of the report texts is bundled with the program (each in its own name). The texts that belong to the report (the section titles, the labels, the narrative sentences, the dates and the numbers) are translated in those languages.

The **kinship terms** that follow a name (*uncle*, *grandmother*, *first cousin*, ...) are in the language of the report, with the form for the sex of the person, in **Italian, German, French, Spanish and Portuguese**. In the other languages they are written in English, even if the rest of the report is translated.

What you wrote in the records (names, notes, titles, places) is never translated.

The titles *Family Book* and *Bibliography* of the two whole-file reports are translated in English and Italian only so far: in the other languages they are written in English.

## The formats

Plain text, Markdown and HTML are always available. **Word, PDF, EPUB and Static Website are plugins**: they are the files `report-docx.jar`, `report-pdf.jar`, `report-epub.jar` and `report-site.jar` in the `plugins` folder of the installation. If one is not there, the format is not offered in the *Save as type* list; copying the file there makes it available the next time the application starts.
 When the report has more than one chapter (a heading of the first level), a **Contents** list with a link to each chapter follows the title.
- **Markdown**: UTF-8. The images are `![caption](path)`, with the path written so that every viewer follows it (spaces, parentheses and accents encoded). The documents of a source are listed by name, not by the whole path of the disk; the citations are bullet lists, and the cropped part of an image is written *x=…, y=…, width×height*. Headings with a record identifier get an anchor, and the internal links work.
- **Plain text**: titles underlined, bullets as `-`, tables as rows separated by `|`, images as `[image: path]`. The bold, italic and code marks are removed.
- **HTML**: one file with its style inside. The images are **linked**, not embedded. The internal links work. The page is declared as English whatever the language.
- **Word**: the headings use the Word heading styles (so the navigation pane works), the tables have a shaded header, the images are embedded and scaled to fit, and the trees are in a monospaced font.
- **PDF**: A4, with a running title and page numbers, and the images embedded (an image larger than the page is scaled down, a smaller one is not enlarged; one that cannot be read leaves only its caption).
  - **Navigation**: the headings are the bookmarks of the file, and when there are at least two headings of the first two levels a **table of contents with page numbers** follows the title; its entries and the links to a record jump to the heading.
  - **Tables**: the header row is repeated on every page, and the columns are as wide as their content.
  - **Fonts**: the fonts are embedded in the file, so it reads the same on any computer. When you press **Generate...** in the *PDF* format, and after the report is built, a list shows only the fonts (installed in your system, or carried by the program) that have every character of this report; choose one, or *Automatic* (the default), which uses a built-in sans-serif (Latin, Greek and Cyrillic) and takes the letters it lacks from the fonts of the system and, last, from the ones the program carries (Noto Sans for Latin, Arabic, Hebrew, Thai, and Chinese, Japanese and Korean, the font of the language of the report first). If no single font has all the characters the list is skipped and *Automatic* is used. A font that forbids embedding is skipped, and one without a bold or italic face is thickened or slanted by the writer.
  - **Extra fonts**: the Noto fonts (Latin, Arabic, Hebrew, Thai, Chinese, Japanese, Korean, Hindi, Bengali) are not in the program: they are in the `fonts` folder beside the `plugins` one. When that folder has no fonts, the report window shows a note and **Download Fonts...**, which opens the list of **Help > Optional Components...** (see [Troubleshooting](troubleshooting.md#optional-components)), where the fonts are downloaded (checked against their published SHA-256) and installed at once. Without them the PDF is written just the same, with the fonts of your system, and a script that none of them has may show missing letters.
  - **Hindi and Bengali**: the shape of these letters depends on the ones around them (conjuncts, vowel signs written before the consonant), which the PDF writer does not do, so each word is shaped by the program and drawn as a vector image with the Noto font it carries, whatever font you chose. The drawing is as sharp as text at any zoom, but these words cannot be selected, copied or searched in the PDF; use Word, EPUB or HTML if you need that.
  - **Right to left**: a report in Arabic, Hebrew and the other right-to-left languages is laid out from right to left.
  - **Trees**: the descendants tree is written in a monospaced font of the system (Consolas, DejaVu Sans Mono, Courier…) and shrunk, down to a limit, so that its longest line fits the page.
- **EPUB**: an e-book (EPUB 3) with a **chapter for each first-level heading** and a table of contents, to read on an e-reader or in a reading app. The images are embedded inside the book, the internal links jump between chapters, a page break is ignored (the text reflows) and the book carries the language of the report.
- **Static website**: a **folder** with a home page (the title page and the contents), **one page for each first-level heading**, named after its title (for example `people.html`, so the addresses stay the same when a chapter is added), a navigation list on every page (only the chapters around the current one, when there are many: the home page lists them all), links to the previous and next page, and the images in an `images` folder. It needs no server and no script: open `index.html` from the disk, or publish the folder as it is. The internal links jump between pages, and the language and its direction (right to left, where it applies) are those of the report. If the folder already exists, the pages and images of the earlier report (listed in the hidden file `.site-manifest`) are replaced and anything else in it is left alone; the site is built aside and put in place only when complete, so a failed report does not damage the previous one. SVG images that contain a script are not copied.
